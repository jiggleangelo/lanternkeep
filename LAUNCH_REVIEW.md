# Launch review fixes

Manifest and plist lines over 2,000 characters are omitted before XML attribute matching and produce an informational limit finding. Manifest permission attributes can span lines. Individual manifest tags are also capped at 2,000 characters. Incomplete, unsupported, redacted or limited permission evidence is explicitly reported as not assessed. Commented-out permissions do not count as evidence.

The default required target SDK is API 36 for standard Android new apps and updates, effective 31 August 2026. The cited Android Developers page was checked on 26 October 2026. Wear OS, Automotive, TV and XR exceptions and granted extensions require human verification; the existing workspace override remains available. Existing saved reports must be regenerated by resubmitting documents to apply updated rules.

Multipart boundary counts are checked before part Message allocation. Only flat forms are accepted. Each part is parsed with headersonly=True, preventing recursive MIME object amplification even when an outer part hides thousands of nested parts. The request, file and 100-part caps remain enforced.

Startup moves corrupt workspace directories to DATA_DIR/quarantine and removes their share pointers. Healthy workspaces continue to load. Quarantined data is inaccessible through workspace and share routes, remains byte-for-byte available to the operator, and still counts toward the data cap. Quarantine is not automatic repair; inspect and recover or remove it through operator filesystem access. Ordinary disk permission or write failures are not silently treated as corrupt JSON.

Blank or invalid privacy-policy dates produce an informational not-assessed R8 finding. Known category omissions still produce a high finding independently of the date. The report and R6 explicitly explain that the permission mapping is partial and analytics, crash reporting, forms and other SDKs can collect data without permission evidence.

All response paths reset the socket write timeout before flushing headers. Request reads retain their existing absolute deadline.

Workspace and share routes share a per-client missing-link limit of 30 failures per 60-second window. Further capability requests receive 429 with Retry-After: 60. Successful requests do not consume the failure budget. Client identity uses the existing trusted-proxy rules. Buckets contain ephemeral HMAC identifiers, remain only in memory, expire on access, and are capped at 4,096 clients. At capacity, new client buckets are temporarily refused rather than evicting active limits. Restart clears the buckets.

Regression coverage is in tests/test_launch_review.py, including a killable subprocess for the manifest CPU attack. The two old default-policy diff expectations now require API 36; explicit API 35 override tests remain. Run the complete suite with python3 -m unittest discover -s tests. Tests were not executed while preparing this change because command execution was prohibited.

No model calls, network calls or simulated production checks were added. Existing made-up sample data and the separate Steward demonstration remain illustrative.
